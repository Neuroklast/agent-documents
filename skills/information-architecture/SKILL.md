# Information architecture and navigation

## Workflow and acceptance

- Inventory content and actions by user task rather than database or organizational structure. Map entry points, objects, relationships, permissions and completion.
- Prioritize frequent and consequential tasks; map alternate paths, return paths and recovery. Keep rare actions contextual.
- Choose navigation by scope: global destinations, local siblings, contextual actions and breadcrumbs for genuine hierarchy. Tabs switch related views; links navigate; buttons act.
- Establish consistent vocabulary. Validate labels and hierarchy using tree testing or task-based evaluation where feasible.
- Specify shareable filters and selections, history, deep links, refresh, invalid/unauthorized routes and state restoration. Search preserves query and scope; distinguish empty results from failure and never reveal inaccessible items.
- Avoid duplicate primary actions, competing navigation, orphan routes and hidden essentials. Output task map, content model, hierarchy and route contract; see [UI](../../frontend/ui.md) and [UX](../../frontend/ux.md).
