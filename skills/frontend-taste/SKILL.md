# Frontend taste

Use the actual product, existing design tokens and representative screen as evidence. Identify visual hierarchy, density, spacing, typography and interaction cues. Flag generic treatment only when it weakens the task or conflicts with the product; no universal aesthetic bans.

- Review real content and representative widths. Point out concrete visual problems, not stylistic labels.
- Prefer existing primitives and deliberate exceptions; do not introduce new visual systems for routine edits.
- Suggest the smallest meaningful improvement and verify the updated screen. If screenshots or reference screens are unavailable, distinguish the unverified judgment.
- For a new visual direction use [visual design](../visual-design/SKILL.md) instead. For implementation use [frontend UI](../frontend-ui/SKILL.md). For full UX acceptance use [UX quality review](../ux-quality-review/SKILL.md).

Output: evidence-backed visual findings and a small set of actionable improvements.
