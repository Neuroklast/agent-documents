# Forms, content design and localization

## Workflow and acceptance

- Request only data necessary for the current outcome; explain unusual requirements in context. Group related fields; disclose conditional fields without losing input.
- Use appropriate native input types, autocomplete, input mode and stable labels. Accept paste and password managers; avoid needless formatting and redundant entry.
- Do not interrupt unfinished input. Preserve drafts, map server errors to fields and explain recovery.
- For multi-step work expose meaningful progress, backtracking and review when consequences warrant it; avoid unnecessary wizard steps.
- Use concrete verbs and nouns, consistent terminology, concise empty/error copy and accessible instructions. Placeholders are not labels.
- Localize complete messages, plurals, RTL, number/date formats, time zones, input conventions and text expansion; separate stored values from display.
- Test keyboard submit, invalid/partial data, network failure, duplicate submit, translation and announcements. Output field contract, copy table and acceptance tests. See [UX](../../frontend/ux.md) and [accessibility](../../frontend/accessibility.md).
